# Contribute Open Source Agent

一个专注于 AI Agent 开源项目贡献的智能助手技能。帮助开发者发现、分析并实施针对核心代理行为的高质量 PR。

## 简介

本项目提供了一套系统化的工作流程，用于：
- 分析 AI Agent 开源仓库，识别核心代理行为相关的贡献机会
- 设计和实现聚焦的 PR，避免无关的周边改动
- 将贡献过程转化为面试就绪的技术证据

## 核心原则

- **专注核心行为**：只处理计划、工具路由/执行、上下文/内存管理、多代理编排、评估轨迹、安全/人工审批、故障恢复等核心代理行为
- **小范围高质量**：保持 PR 范围小到维护者可以在合理时间内审查
- **实际可验证**：每个改动都应该可以通过测试或手动验证

## 工作流程

### 1. 明确贡献目标
- 确定核心代理领域（计划、工具、上下文、内存、编排等）
- 确定技能栈（Python、TypeScript、Go、Node、MCP 等）
- 设定时间范围（默认 1-2 周内可完成的 PR）

### 2. 选择候选仓库
- 刷新仓库池的 GitHub 信号（近期提交、Issues、PR、标签、贡献指南）
- 按核心代理适配度、活跃度、可审查性、Issue 质量、面试价值排序
- 降低核心代理 Issues 陈旧、PR 长期未审查、贡献规则不明确的仓库优先级

### 3. 筛选贡献机会
- 优先筛选开放 Issues，但只保留影响核心代理行为的
- 偏好活跃的、未分配的、有明确预期行为和可复现步骤的 Issues
- 检查无关联或进行中的 PR 冲突
- 如果 Issues 较少，检查核心代理模块的测试缺口

### 4. 建立项目理解
- 阅读 README.md、CONTRIBUTING.md、包/测试配置
- 总结核心代理循环、计划方式、工具层、状态/内存模型、评估/测试设置、安全/审批模型
- 运行文档化的快速启动或现有测试

### 5. 选择 PR 方向
- 按核心代理影响、维护者接受概率、实现规模、可测试性、面试价值排序
- 对于非平凡的行为变更，先草拟 Issue 或讨论评论，询问维护者是否接受该方向
- 未经维护者信号或用户明确批准，不进行大型功能、新依赖、公共 API 变更或广泛重新设计

### 6. 设计优先于编码
- 定义核心代理行为变更或测试范围、范围外事项、成功标准、约束、变更文件
- 当设计不明显时比较 2-3 个实现选项
- 保持推荐计划向后兼容，首选第一个 PR 改动行数在 300 行以内

### 7. 保守实现
- 编码前阅读每个将要变更的文件
- 匹配已有的命名、类型、注释、格式化和测试风格
- 偏好扩展点而非侵入式重写
- 保持每一步可运行，并在有意义的变更后验证

### 8. 准备 PR
- 草拟包含问题、解决方案、变更、测试、审核者注释的 PR
- 包含确切的测试命令和结果
- 如需认证或网络访问才能实际打开 PR，请求权限并报告 URL 或剩余手动步骤

### 9. 保留面试证据
- 记录仓库上下文、核心代理行为变更、触及的文件、测试、权衡、维护者反馈、最终 PR 状态

## 核心代理行为范围

### ✅ 在范围内

- **代理循环和计划**：修复代理选择下一步的方式、添加或测试工具失败后的重新计划、跨续接/恢复保留任务状态、改进终止条件
- **工具路由和执行**：修复工具选择、参数验证、工具结果处理、减少相似工具之间的混淆、添加工具调用参数或失败工具调用的测试
- **上下文和内存**：修复压缩或修剪期间重要工具结果的丢失、将系统/开发者指令与会话内容分开保留、改进影响代理决策的内存检索
- **多代理协调**：修复交接协议、角色路由、共享状态或聚合、添加工作器/编排器交互测试
- **评估轨迹和代理测试**：添加计划/工具行为的轨迹级测试、断言工具调用和中间决策
- **安全、权限和人工参与**：修复高风险工具使用前缺少确认的问题、保留后续步骤的人工反馈
- **故障恢复**：将工具/Provider 错误转换为可恢复的代理状态、在现有设计支持的地方重试/回退/重新计划

### ❌ 默认范围外

- 仅文档或仅翻译的 PR
- 仅 UI 的润色、主题、布局、图标或文案变更
- 仅设置、仅安装、仅部署或仅打包工作
- 依赖升级或锁定文件变更
- 格式化、仅 Lint 或广泛清理 PR
- 不影响代理行为的通用错误修复
- 没有改进核心代理行为的大型新集成

## 输出格式

### 仓库排名

| 仓库 | 核心代理适配度 | 健康信号 | 可能的入口文件 | 最佳 PR 方向 | 风险 |
|---|---|---|---|---|---|

### 机会分析

| 排名 | 来源 | 核心代理行为 | 入口文件 | 预期工作量 | PR 冲突检查 | 接受风险 | 测试策略 | 面试价值 |
|---|---|---|---|---|---|---|---|---|

### 实施任务

完成时返回：
- 变更文件
- 运行的测试
- 剩余风险
- PR 草稿或 PR URL

### 面试准备

使用实际贡献产物生成简洁的 STAR 风格故事：
- **背景**：仓库的代理做什么以及为什么这个模块重要
- **贡献**：修复、保护或测试了什么行为
- **过程**：3-5 个技术决策及每个决策的原因
- **结果**：PR 状态、测试、变更文件、可衡量的影响（如果有）、维护者反馈
- **挑战**：1-2 个真正的困难及如何解决
- **展示的能力**：架构阅读、测试设计、API 兼容性、代理评估、工具路由、上下文管理或维护者沟通
